Notes on the three I did this session:

- **PL-7:** besides correcting the "installation-wide" wording, I fixed a bug I found on the way. For remote Claude and ACP agents, `save_skill` recorded the skill's name but threw away its content. It now saves through `POST /api/skills`.
- **PL-6:** `message_agent` has a new route, `POST /api/tasks/:id/messages`, which requires `task:conversation:message`. Its old route, `/signal`, required the broader `task:signal`. As a result, a token holding only `task:signal` can no longer use `message_agent`, though it can still send the same follow-up through `signal_task`.
- **PL-8:** the "multi-replica double apply" claim is wrong for the stored requests themselves. On Postgres every store transaction takes a lock shared across processes, so request and resolve can't lose updates. The real bug was elsewhere: the "decision in progress" guard only existed in one process's memory, and approving a scope expansion widens the task's access before the request is marked resolved. The new test reproduced it: a denial sent to a second gateway instance was accepted mid-approval, and the task kept the wider access anyway. Decisions now take a short claim in the shared store; a claim left by a crashed instance expires after five minutes.

What remains:
- **PL-5 nit (low):** a task that holds no merge domain now gets a generic "not in merge domain" error rather than a clearer message.
- **PL-8 growth (low):** each organization's permission requests still sit in one list that is never pruned and is rewritten on every request. That's a slow growth problem, not a correctness one.

Problems outside my batch that I noticed but did not fix:
- `AuthorizationRequests.resolve` in `api.ts` looks like it has the same side-effect-before-claim pattern as PL-8. I have not checked it.
- The in-turn tool list still includes `save_skill` for providers whose turns may not have gateway access. Where the gateway is unreachable, the tool now fails with a clear error instead of silently dropping the skill.
